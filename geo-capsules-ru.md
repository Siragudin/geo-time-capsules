# 📜 Концепт-манифест проекта: «Гео-Капсулы Времени» (Digital Time Capsules)

## Суть проекта

Международный веб-сайт (Web App) — интерактивная гео-карта человеческих воспоминаний, надежд и посланий, привязанных к реальному пространству и времени. Пользователи «закапывают» цифровые сейфы с текстом и медиафайлами строго в тех координатах, где физически находятся, с отложенным таймером открытия на годы вперёд.

---

## 🎨 1. Пользовательский опыт (UX/UI)

- **Интерфейс:** полноэкранная интерактивная карта, подстраивающаяся под геолокацию пользователя.
- **Маркеры на карте** — с автоматической кластеризацией, чтобы карта не лагала:
  - 🔐 **Закрытая капсула (янтарный маркер):** содержимое заблокировано на сервере. Виден только таймер обратного отсчёта и подсказка автора.
  - 🔓 **Вечный архив (зелёный маркер):** открытая капсула, ставшая историческим памятником. Доступна для чтения любому.
  - ⏳ **Самоликвидация (красный мигающий маркер):** открытая капсула с запущенным таймером безвозвратного уничтожения.
- **Процесс создания:** сайт запрашивает GPS-координаты, пользователь может скорректировать маркер вручную, прикрепить файл, выбрать дату открытия и сценарий жизни капсулы.
- Капсула проходит модерацию перед публикацией и появляется на карте только после успешной проверки. Техническая механика процесса пользователю не показывается — только факт, что проверка идёт.

---

## 🕵️ 2. Анонимность

Анонимность публичная, а не системная:

- Любой пользователь может посмотреть чужую открытую капсулу, не зная, кто её автор.
- Платформа знает автора каждой капсулы — через обязательный аккаунт.
- Автор остаётся неизвестным другим людям, если только сам не раскрыл себя в содержимом (фото, видео, голос, подпись).

### Вход и аккаунты
- Обязательная регистрация: email/пароль + OAuth (Google, Яндекс и др.).
- Личный кабинет со списком собственных капсул (виден только автору).
- Привязка лимитов на создание капсул к аккаунту, а не к IP.

---

## 🔒 3. Жизненный цикл капсулы

Автор фиксирует судьбу капсулы в момент создания без возможности редактирования контента:

1. **Режим «Вечный архив»** — капсула открывается в назначенный день и остаётся на карте навсегда как цифровая история места. Автор не может удалить капсулу самостоятельно.
2. **Режим «Самоликвидация»** — автор указывает срок жизни капсулы после открытия (например, 1 месяц). По истечении срока капсула стирается из базы и S3 без возможности восстановления.

### Удаление контента
- Удаление возможно только на стороне администрации — по итогам жалобы или модерации, обнаружившей нарушение постфактум.
- Публичная кнопка «Пожаловаться» на каждой открытой капсуле.
- Механизм запроса на удаление по праву на забвение (GDPR) — с верификацией личности заявителя.

### Сроки открытия капсулы
- **Минимум — 1 год.**
- **Максимум — 100 лет**, с оговоркой в интерфейсе:
  > «Мы храним капсулы на серверах в нескольких независимых юрисдикциях и делаем резервные копии. Мы не можем дать абсолютную гарантию на 100 лет из-за форс-мажорных обстоятельств, но обязуемся прилагать все усилия для сохранности.»
- Параметры MIN/MAX хранятся как конфигурируемые значения на бэкенде.

## ⚙️ 4. Модерация контента

Пользователям не нужно знать механику модерации — достаточно знать, что она есть.

### Схема проверки

| Тип контента | Метод проверки |
|---|---|
| Текст | Лёгкий ИИ-классификатор токсичности/угроз |
| Фото | Лёгкий image-moderation API + обязательный hash-check по базам CSAM (PhotoDNA/NCMEC) |
| Аудио | Транскрипция → текстовый классификатор |
| Видео | Скриншоты через каждые X секунд → image-moderation + hash-check, отдельно — транскрипция аудио-дорожки → текстовый классификатор |

### Процесс

1. Пользователь создаёт капсулу → статус «pending», не отображается на карте.
2. Автоматическая проверка контента.
3. Если контент чистый → капсула публикуется на карте.
4. Если результат неоднозначный → капсула уходит в очередь human-модерации; если не подтверждена как допустимая — удаляется.
5. Жалобы пользователей — второй уровень защиты для открытых капсул.
6. При отклонении капсулы автору сообщается только общая причина, без раскрытия деталей алгоритма.

Тарификация влияет на скорость/приоритет прохождения очереди модерации, а не на её строгость. Глубина и обязательность проверки одинаковы для всех тарифов.

## 🗺️ 5. Институциональные пользователи

Музеи, университеты, школы, архивы, создающие капсулы как долгосрочные культурные объекты.

- Партнёрский/эндаумент-тариф — разовый или ежегодный взнос в фонд устойчивости проекта, а не за объём хранения.
- Часть доходов направляется в резервный фонд, покрывающий минимальные расходы на хостинг даже при закрытии основного бизнеса.
- Юридически прописывается, что происходит с архивом капсул при закрытии компании (обязательство передачи данных партнёрской НКО/фонду).

## ⚙️ 6. Техническая архитектура

- **Фронтенд:** SPA (React/Vue), карта — Google Maps JS API либо MapLibre/OpenStreetMap. Полное сжатие медиафайлов на клиенте (Client-Side Compression) до лимита бесплатного тарифа.
- **Бэкенд:** FastAPI / Node.js / Go. Authoritative Server — контент закрытых капсул физически не передаётся в браузер до даты открытия; серверная проверка `currentTime >= unlockAt`.
- **Хранилище:** PostgreSQL + PostGIS для гео-индексированных данных; медиафайлы — в защищённом S3-облаке. Доступ к медиа открытых капсул — только через временные presigned URLs (15 минут).
- **Надёжность:** мультирегиональное резервирование серверов (разные страны/юрисдикции).
- **Защита от спама:** reCAPTCHA v3 + лимиты на создание капсул, привязанные к аккаунту.

---

## 💼 7. Монетизация

- **Бесплатный тариф:** текст + фото до 5 МБ.
- **Платный тариф:** видео и аудио, расширенный объём (50–100 МБ), уникальная золотая иконка сейфа на карте.
- **Реклама** — только в интерфейсе сайта (сайдбар, футер, лендинг, статистика), не внутри карточек и модальных окон открытых капсул.
- **Институциональный/эндаумент-тариф** — для музеев, университетов, архивов.
- **Кнопка «Поддержать проект»** — донаты от частных пользователей и институций.
